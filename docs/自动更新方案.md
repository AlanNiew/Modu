# 自动更新方案（Tauri Updater）

> 状态：实施中 · 目标版本 v0.3.1
> 关联：`docs/开发任务书.md`（§2.1 版本锁定、附录 D 里程碑）、`docs/用户手册.md`

## 1. 目标与非目标

**目标**

1. 应用内「检查更新」：发现新版本 → 展示版本号与更新说明 → 一键更新。
2. 更新过程不弹 NSIS 安装向导：下载 → 校验签名 → **静默安装** → 自动重启。
3. 启动时可选静默检查（默认开启，可在设置里关闭），有更新才提示。
4. 更新包必须通过 Ed25519 签名校验，杜绝中间人替换。
5. 失败可解释：下载失败 / 校验失败 / 安装失败分别给出提示与「手动下载」入口。

**非目标**

- 不做「运行中原地替换、不重启」（Windows 文件锁，native 代码必须重启生效）。
- 不做前端资源热替换（需要剥离前端到可写目录 + 完整性校验，安全与复杂度不成比例）。
- 不引入自建更新服务器：直接用 GitHub Releases 上的 `latest.json`。

## 2. 方案对比与选型

| 方案 | 无向导 | 免提权 | 覆盖安装版/便携版 | 复杂度 | 结论 |
|---|---|---|---|---|---|
| A. Tauri 官方 updater（NSIS 静默） | ✅ | 视安装目录 | 安装版 | 低 | **采用** |
| B. 便携版自更新（改名 exe + 重启） | ✅ | ✅ | 仅便携版 | 中 | 后续可选 |
| C. 运行中热更新 | — | — | — | 高、有安全风险 | 不做 |

选型理由：官方 updater 已实现下载、签名校验、静默安装、重启、跨平台；我们只需要发布流程 + UI。

## 3. 架构与数据流

```
启动 / 点击「检查更新」
        │
        ▼
GET https://github.com/AlanNiew/Modu/releases/latest/download/latest.json
        │   （含 version / notes / pub_date / platforms.windows-x86_64.{signature,url}）
        ▼
比较 version 与当前版本（tauri getVersion）── 无更新 → 结束
        │ 有更新
        ▼
下载 NSIS 安装包到临时目录
        │
        ▼
用内置公钥验签（失败即中止，绝不执行）
        │
        ▼
静默执行安装包（installMode: quiet）
        │
        ▼
relaunch() 重启到新版本
```

关键点：

- 公钥编译进二进制（`tauri.conf.json → plugins.updater.pubkey`），私钥只在发布机/GitHub Secrets 保存；
- 私钥丢失 = 无法再发布更新（旧版本会拒绝一切验签失败的包），必须备份；
- endpoint 固定为 GitHub Releases 的 `latest` 别名，不跟随页面跳转，避免被劫持。

## 4. 依赖与配置

**Rust（`src-tauri/Cargo.toml`）**

```toml
tauri-plugin-updater = "2"
tauri-plugin-process = "2"
```

**前端（`package.json`）**

```json
"@tauri-apps/plugin-updater": "^2.14.1",
"@tauri-apps/plugin-process": "^2.4.0"
```

**权限（`src-tauri/capabilities/default.json`）**

```json
"updater:default",
"process:default"
```

**`src-tauri/tauri.conf.json`**

```jsonc
"bundle": {
  "createUpdaterArtifacts": true,
  "windows": { "nsis": { "installMode": "currentUser" } }
},
"plugins": {
  "updater": {
    "pubkey": "<生成的公钥>",
    "endpoints": ["https://github.com/AlanNiew/Modu/releases/latest/download/latest.json"],
    "windows": { "installMode": "quiet" }
  }
}
```

> `installMode: currentUser` 是前提：装到 `%LOCALAPPDATA%` 静默更新才不会弹 UAC。
> 若安装在受保护目录（如 `D:\Windows Tools`，属主 Administrators），静默安装仍会触发 UAC。

## 5. 密钥管理

1. 生成：`pnpm tauri signer generate -w <path> -p <password> --ci`（Ed25519，输出公钥）。
2. 私钥与密码保存在**仓库外**（本机 `_modu-updater/`），并立刻备份到密码管理器 / 加密盘。
3. CI 或本地发布时通过环境变量注入：

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = (Get-Content <key path> -Raw)
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = "<password>"
```

4. 公钥写进 `tauri.conf.json`，随源码公开（这是设计如此）。
5. **丢失私钥的后果**：已发布版本无法接受新包，用户只能手动下载重装。务必两处备份。

## 6. 发布流程（每次发版）

```powershell
# 1) 改版本号（三处：package.json / Cargo.toml / tauri.conf.json）
# 2) 写更新说明 docs/release-notes/vX.Y.Z.md
pwsh scripts/build-release.ps1 -Version 0.3.1 -NotesFile docs/release-notes/v0.3.1.md
#    → 读取 _modu-updater/env.ps1 注入签名密钥
#    → pnpm tauri build --bundles nsis（产出 安装包 + 安装包.sig）
#    → 生成 latest.json（签名内联）
#    → 打包便携 ZIP
# 3) 在 GitHub 建 Release / 上传：安装包、便携 ZIP、latest.json
# 4) 验证：安装上一个版本 → 点检查更新 → 应静默升级并重启
```

`latest.json` 结构：

```json
{
  "version": "0.3.1",
  "notes": "本版更新内容…",
  "pub_date": "2026-11-05T16:30:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "<安装包.sig 的内容>",
      "url": "https://github.com/AlanNiew/Modu/releases/download/v0.3.1/<安装包>.exe"
    }
  }
}
```

## 7. 客户端行为

| 场景 | 行为 |
|---|---|
| 启动（自动检查开启） | 后台拉清单；有更新 → 弹「发现新版本」对话框；无更新静默 |
| 手动「检查更新」 | 立即检查，无更新也提示「已是最新版本」 |
| 开发模式（`pnpm tauri dev`） | 跳过检查，提示「开发模式不支持」 |
| 下载中 | 进度条（已下载/总字节 + 百分比），可取消 |
| 下载/验签成功 | 「正在安装，应用将重启」→ 静默安装 → `relaunch()` |
| 下载失败/网络错误 | 提示 + 「重试」+「手动下载」链接 |
| 验签失败 | 明确提示「更新包校验失败，已中止」并给出手动下载（不执行包） |

## 8. 兼容、回滚与安全

- **数据库**：更新后首次启动跑 `migrate()`；迁移只做向前兼容（旧库 → 新库单向）。发版前必须跑 `cargo test --lib` 覆盖迁移用例。
- **回滚**：NSIS 覆盖安装；若新版本启动即崩，用户可手动重装上一版本安装包（Release 页面保留历史附件）。自动回滚不在本版范围。
- **降级保护**：updater 只在远端版本 **大于** 当前版本时提示，不提供降级。
- **签名**：验签失败一律中止；不提供「忽略签名」开关。
- **隐私**：检查更新只发一个 GET，不带任何用户标识。

## 9. 测试计划

1. 单测：`latest.json` 解析、版本比较（`0.3.10 > 0.3.9`）、开发模式短路。
2. 端到端（本机）：
   - 构建 v0.3.1（含 updater）并安装到 `%LOCALAPPDATA%`；
   - 构建 v0.3.2 安装包 + `.sig`，生成本地 `latest.json`，用 `python -m http.server` 临时托管；
   - 把 v0.3.1 的 endpoint 临时指向 `http://127.0.0.1:8123/latest.json` 验证「检查 → 下载 → 静默安装 → 重启 → 版本变 0.3.2」；
   - 再把 endpoint 改回 GitHub。
3. 异常用例：断网、篡改 `latest.json` 的 signature、URL 404。
4. 真机回归：升级后书架、进度、书签、批注完整。

## 10. 验收清单

- [ ] 应用内可检查更新，显示版本号与更新说明
- [ ] 更新过程无 NSIS 向导，仅有应用内进度
- [ ] 更新后自动重启，版本号变化
- [ ] 签名错误时中止并提示，不执行安装包
- [ ] 更新后数据库与用户数据无损
- [ ] 开发模式不触发更新
- [ ] 发布脚本一条命令产出 安装包 + 便携 ZIP + latest.json

## 12. 已知限制

- 安装在受保护目录时，静默安装仍会弹一次 UAC（根治办法：per-user 安装或代码签名 + per-machine）。
- GitHub Releases 无灰度能力；如需 beta 通道，可在 endpoint 返回不同清单（后续）。
- 便携 ZIP 无法被 updater 更新（用户需手动替换），后续可用方案 B 补。

## 13. 验证记录（v0.3.1）

### 已验证（本机，CDP 自动化）

| 环节 | 证据 |
|---|---|
| 插件加载 | 0.3.1 生产构建启动正常，updater / process 两个插件初始化无报错 |
| 拉取清单 | 弹窗显示「当前版本 v0.3.1 → 发现新版本 v0.3.2」，`notes` / `pub_date` 正确渲染 |
| 下载 + 验签 | 载荷签名与清单版本不一致时，客户端明确拒绝并给出「The update was signed for version 0.3.1 but the update endpoint announced version 0.3.2 … may have been tampered with」——说明下载、签名解析与版本绑定校验均真实执行 |
| 失败兜底 UI | 校验失败后展示「可以稍后重试 / 手动下载」，不执行安装 |
| 配置校验 | endpoint 为 http 时插件启动即拒绝（`The configured updater endpoint must use a secure protocol like https`）——https 强制生效 |

### 未在本环境验证

- **静默安装 + 自动重启**：本机构建环境里 NSIS 静默安装会挂起（`/S` 与 `/D=` 均 >180s 无产物；既有 0.3.0 装在管理员属主的 `D:\Windows Tools`，权限/提权交互被环境阻断）。该环节需在真机验证。
- 因此本轮交付口径为「检查 / 下载 / 验签 / 失败兜底已自动化验证；安装与重启待真机验收」。

### 本地复测方法

1. 测试构建里临时加 `"dangerousInsecureTransportProtocol": true`（**仅测试，绝不进正式包**），endpoint 指向 `http://127.0.0.1:8123/latest.json`。
2. 清单 `version` 必须大于客户端版本，且 `signature` 必须来自**版本号一致**的产物（签名 trusted comment 里带 `version:`，跨版本会被拒）。
3. 用 `python -m http.server 8123 --bind 127.0.0.1` 托管安装包 + `latest.json`。
4. 建议用独立 `identifier` / `productName` 构建测试客户端，避免撞上正式安装。
