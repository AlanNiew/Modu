## 1. 项目概述

### 1.1 背景

旧版阅读器（PyQt5）功能基本齐全：书架、目录、书签、搜索、进度记忆、双主题、排版设置、沉浸模式都能跑。
用户的核心反馈是**"功能还行，只是看起来不是很舒服"**。

代码审计后的结论是：这不是换配色能解决的问题，而是**渲染层选错了**。

### 1.2 旧版实现审计

| 模块 | 旧版实现 | 评价 |
|---|---|---|
| 正文渲染 | `QTextBrowser.setHtml()` | ⚠ **核心痛点**。Qt 富文本只支持 CSS 2.1 子集：无 flex/grid、无 web 字体、无分栏、无 `text-align: justify` 的精细控制、无字距/连字、无 `@supports`。字体、行高、页边距的天花板就在这里 |
| 分页 | 无，靠竖直滚动条 | 无真实"页"概念，无页码，翻页感缺失 |
| 章节切换 | 每次销毁重建 `QTextBrowser` | 闪白、丢失滚动位置、无预加载 |
| 图片 | 解析完成后转 `data:base64` 内联进 HTML | 大图/图多的书内存暴涨、首屏变慢 |
| 目录 | spine 顺序 + `toc_map` 标题模糊匹配（`endswith` 猜测） | 树形层级被拍平成一维列表 |
| 搜索 | 逐章 `get_text()` 子串匹配 | 只能定位到"章"，无结果列表、无上下文片段、无全书命中统计 |
| 进度 | 章节索引 + 滚动条像素值 | **像素锚点脆弱**：换字号/改窗口即失准 |
| 书签 | 同上（章号 + 像素） | 同上 |
| 设置 | `QSettings`（写 Windows 注册表）+ JSON 字符串 | 无 schema 版本、无迁移、字段散落 |
| 主题 | 两套 QSS（Catppuccin）+ 4 个阅读预设 | 视觉方向是对的，但受 Qt 渲染限制 |
| 打包 | PyInstaller 单文件 43 MB | 冷启动慢（解压到 temp） |
| 工程 | 单文件 1323 行，全局状态 + 裸字典 | 无类型、无测试、改动易回归 |

**五个根因**（决定了重做时必须换掉的架构选择）：

1. **渲染层**：`QTextBrowser` 无法呈现现代排版的细节 —— 这是"不舒服"的根因。
2. **锚点模型**：像素滚动值不是稳定的文档坐标。
3. **章节即重载**：整页重建带来闪烁与状态丢失。
4. **数据结构扁平**：`chapters[]` + 裸 dict 无法表达 `书 → 章 → 块 → 批注` 的层级。
5. **单体无类型**：1205 行里所有状态共享一个命名空间。

### 1.3 目标："舒服"的六个可测量维度

这次的核心目标**不是"加功能"**，而是把阅读体验做对。以下每条都能验收：

| 维度 | 目标 | 验收指标 |
|---|---|---|
| 版面 | 行长、留白、页边距可调且默认得体 | 中文行宽可调（版心 520–1000px，约 32–46 字）；页边距 **0–64px 独立可调，默认 24**（v0.4 重新独立；v2 时期「由版心推导」的口径废止，见 docs/CHANGELOG-TASKS）；默认值在 1366×768 上不出现"满屏字" |
| 字体 | 真·字体控制 | 字号 14–32；行高 1.2–2.4；字重 400/700 正确；支持导入 TTF/OTF；衬线/非衬线/等宽 6 套默认 |
| 节奏 | 翻页顺滑、无闪白 | 翻页 < 50ms；无白屏；重排 < 150ms；前后章预加载 |
| 导航 | 随时知道在哪 | 嵌套目录树；全书百分比 + 本章页码（第 3/17 页）；进度条可拖动跳转 |
| 专注 | 沉浸时不打扰 | 沉浸模式下正文占屏 ≥ 85%；呼出式 UI；Esc 一键退出 |
| 一致 | 记住一切 | 字号/主题/窗口/进度/书签即时持久化，重启 100% 还原 |

### 1.4 非目标（本期明确不做）

- PDF / MOBI / AZW3 / CBZ 全格式阅读（架构预留，不做实现）
- 在线书城、账号体系、云同步、社交
- DRM（加密 EPUB）解密 —— 明确不支持，遇到时给出清晰提示
- 移动端 / 网页版
- 全文朗读之外的多媒体（音频书、视频）

### 2.2 关键决策记录（ADR）

#### ADR-001 渲染引擎：vendor foliate-js 的分页核心，而非从零自研

- **决策**：把 [foliate-js](https://github.com/johnfactotum/foliate-js)（MIT）的 `view.js` / `paginator.js` / `epubcfi.js` / `overlayer.js` / `footnotes.js` 固定 commit 复制进仓库，用一层 TypeScript 适配器（`src/renderer/`）驱动；**不使用**它的 `epub.js` 解析器（解析交给 Rust，见 ADR-002）。
- **理由**：
  - foliate-js 是 Linux 著名阅读器 Foliate 的渲染内核，专攻"reflowable 排版 + 分栏分页"，已处理图片跨页、`break-inside`、脚注、RTL、日文纵排、进度换算等长尾问题，自研需 1–2 周且效果更差。
  - 纯 JS、零硬依赖、模块化、可无构建直接 ESM 引入；许可为 **MIT**（已核对 `LICENSE`）；**上游无 npm 包、无 release**，README 明确建议以 git submodule 引入 → 本项目改为"固定 commit 复制进 `src/renderer/vendor/foliate/`"，不走依赖管理。
  - 它的 `book` 接口是鸭子类型（archive loader 只需提供 `.entries` / `.loadText` / `.loadBlob` / `.getSize` 四件套），可以用 Tauri 命令喂数据，不需要把 zip 读进 JS。
  - 相比 epub.js：foliate 用 **Range 定位而非 CFI**、用二分法求精确可见区、支持 >2 列、滚动↔分页切换不重载章节 —— 与本项目 ADR-004 的 Locator 设计同向，省掉 CFI 这一层。
- **替代方案**：
  - 全自研 paginator：可控但成本高、边界情况多，仅在 M0 spike 失败时启用（保留 `ReaderRenderer` 接口，可替换）。
  - epub.js (futurepress)：仓库仍低速维护（最后提交 2026-03），但 npm 上的 `epubjs@0.3.93` **发布于 2022-02**，落后仓库约 4 年；无 search 模块；分页同为 CSS multicol 且质量不如 foliate。只有需要 **EPUB CFI 互操作**（跨应用书签/批注交换）时才值得换。
- **风险与对策**：作者声明 "this library itself is *not* stable. Expect it to break and the API to change at any time." → 固定 commit、不跟随升级、适配层隔离（`ReaderRenderer` 接口）；vendor 代码无 `d.ts` → 自写最小类型声明；M0 用 1 天时间盒验证（spike 失败则回退自研 paginator）。

#### ADR-002 解析位置：Rust 负责 EPUB 容器，前端不碰 zip

- **决策**：Rust 打开 zip、解析 `container.xml → OPF → manifest/spine/metadata`、EPUB3 `nav.xhtml` 与 EPUB2 `toc.ncx` 双通道、封面提取、字数统计、章节纯文本抽取；前端通过命令拿结构化 JSON 与 HTML。
- **理由**：
  - zip 内资源（图片/CSS/字体）需要按路径按需流式返回，Rust 侧可做 LRU 缓存与句柄复用，避免每次翻页重开 zip。
  - 大书（50 MB+）只解析需要的部分；JS 侧解析会让首屏内存翻倍。
  - 解析逻辑可被 `cargo test` 用固定语料单测，这是旧版最缺的部分。

#### ADR-003 资源服务：注册自定义协议 `epub://`，不用 `asset:`、不用 `data:`

- **决策**：Rust 用 `register_uri_scheme_protocol("epub", …)` 注册协议，URL 形如 `epub://<bookId>/<zip 内路径>`；**Windows/Android 上 Tauri 实际暴露为 `http://epub.localhost/<bookId>/<path>`**（macOS/Linux 才是 `epub://localhost/…`），CSP 必须按前者写。
- **关键约束（决定了整体架构）**：自定义协议页面与主页面**不同源**（`http://epub.localhost` ≠ `http://tauri.localhost`）。因此**章节 HTML 不能直接用协议 URL 作 `<iframe src>`** —— 那样父页面拿不到 `contentDocument`，无法注入 CSS、测量 `scrollWidth`、拦截链接点击。正确形态：章节 HTML 以 `blob:`（或 `srcdoc`）进入**同源** iframe，`epub://` 只服务 iframe 内部的子资源（`<img>`、`<link rel=stylesheet>`、`@font-face`），由 WebView2 的 `AddWebResourceRequestedFilter` 全局拦截——这正是 foliate-js 假定的模型。
- **理由**：
  - `asset:` 只能映射真实文件系统路径，**无法**读取 zip 内条目。
  - `data:` 内联（旧版做法）会让大图把内存吃满，且无法被 CSS `url()` / `@font-face` 引用。
  - 自定义协议可同时服务 `<img>`、`<link rel=stylesheet>`、`@font-face`，并带上正确的 `Content-Type` 与 `Access-Control-Allow-Origin: *`。

#### ADR-004 进度锚点：文本锚点（quote + offset + fraction），不是像素

- **决策**：定位符 `Locator` 采用"章节 href + 文本引文 + 字符偏移 + 章节内比例 + 全书进度"的复合锚点（详见 §4.4）。恢复时按"引文 → 偏移 → 比例"三级回退。
- **理由**：旧版用滚动条像素，改字号就失效。文本锚点跨字号、跨窗口、跨设备稳定，也是高亮/批注的唯一可靠基础。

#### ADR-005 持久化：Rust 内部用 rusqlite，不用 `tauri-plugin-sql`

- **决策**：所有 SQL 留在 Rust（`rusqlite`，bundled SQLite，编译期启用 FTS5），前端只调用领域命令（`library_import`、`progress_save`…）。
- **理由**：
  - 前端拿不到 SQL 就等于没有注入面；表结构演进只在一处。
  - `tauri-plugin-sql` 走 sqlx，FTS5 支持取决于编译特性，且会把 schema 散落到前端；本项目的搜索需要可控的分词策略。
  - 迁移用 `PRAGMA user_version` 手写迁移，比插件迁移更直观。

#### ADR-006 视觉：自建设计系统，沿用 Catppuccin 色系基因

- **决策**：Tailwind + CSS 变量 tokens，深色默认；保留旧的 4 个阅读预设（深色/浅色/护眼黄/护眼绿）并新增"跟随系统"；不做花哨动效，最大位移动画 200ms。
- **理由**：用户的旧版配色偏好是有效信号（Catppuccin Mocha/Latte），直接沿用色号能降低陌生感；但组件结构、层级、留白要重做。

### 2.3 Windows 平台与打包决策

- **原生产物**：**只做 NSIS，不做 MSI**。MSI 依赖已废弃的 VBSCRIPT 可选功能（症状 `failed to run light.exe`）且只能在 Windows 上构建；NSIS 默认 per-user 安装（`%LOCALAPPDATA%`，免管理员）。
- **WebView2 安装策略**：保持默认 `downloadBootstrapper`（安装包最小，联网时自动装）。若你做离线分发，改 `embedBootstrapper`（+~1.8 MB）；`offlineInstaller`（+127 MB）/`fixedRuntime`（+180 MB）不采用。另设 `minimumWebview2Version: "110.0.1531.0"`。
- **拖拽导入**：用 Tauri 的 `DragDropEvent`（`Enter { paths, position }` / `Over` / `Drop { paths, position }` / `Leave`，前端 `onDragDropEvent`），**不要**用 HTML5 拖放（需把窗口 `dragDropEnabled` 关掉，反而失去原生路径）。注意该枚举 `#[non_exhaustive]`，匹配要带兜底分支。
- **读文件**：`.epub` 的读取与解析全部在 Rust 命令里完成，路径由 dialog 插件返回后直接交给 Rust；**前端不碰文件系统**（也就绕开了 `fs:scope` 权限矩阵，详见 §2.1 注）。
- **中文/长路径**：路径全程用 Rust `PathBuf` 传递，禁止把中文路径拼进 URL；>260 字符路径视为风险项，导入时 `canonicalize` 并给出可读错误。
- **高 DPI**：Tauri 窗口配置尺寸是逻辑像素，涉及坐标的 API 用 `PhysicalPosition/Size`，两者不可混算；分页测量一律用 `getBoundingClientRect`（CSS 像素），避免 DPI 换算错误。

  %APPDATA%\<app-id>\ :  library.db  covers\  cache\  fonts\  settings.json  logs\

### 3.2 模块职责

**前端（`src/`）**

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `app/` | 启动、路由（Shelf ↔ Reader）、全局错误边界、主题 Provider | 不碰业务数据 |
| `features/shelf/` | 书库网格/列表、排序筛选、导入交互、右键菜单 | 不解析 EPUB |
| `features/reader/` | 阅读器外壳：顶栏、侧栏（目录/书签/搜索页签）、底栏进度、设置抽屉 | 不直接算分页 |
| `renderer/` | 唯一与 foliate 内核交互的地方：加载章节、注入 CSS、跳转、取当前 locator、高亮渲染 | 不渲染 UI 外壳 |
| `features/search/` | 查询输入、结果列表、上下文高亮、上/下条跳转 | 不做全文扫描（Rust 做） |
| `stores/` | Zustand：`libraryStore` `readerStore` `settingsStore` `uiStore` | 不做持久化（Rust 做） |
| `shared/` | 设计 token、UI 原语、hooks（防抖/快捷键/尺寸监听）、类型定义 | 无业务逻辑 |

### 3.3 关键数据流

1. **导入书籍**：`dialog 选文件` → `library_import(paths)` → Rust：算 hash/大小 → 开 zip → 解析 OPF/导航 → 提取封面（解码→缩略图→webp 落盘）→ 统计章节与字数 → 写 `books/chapters` 事务 → 后台异步建 FTS 索引 → 返回 `BookSummary`。
2. **打开书籍**：`book_open(bookId)` → 返回 `BookDetail{meta, toc[], spine[]}` → 前端建 `ReaderSession` → `progress_get` 取 locator → `renderer.goTo(locator)` → 渲染层 `get_section_html(href)` + `epub://` 拉资源 → 分页 → 用户可见。
3. **翻页**：纯前端（paginator 内部 `next()`）→ 跨章时 `get_section_html(下一章)`（预加载命中则不等待）→ 渲染 → `progress_save`（2s 节流）。
4. **搜索**：输入 300ms 防抖 → `search_book(bookId, q)` → Rust FTS 查询返回 `{href, ord, snippet, matchOffset}` → 列表渲染 → 点击 → `renderer.goTo(href + 文本锚点)` → 命中高亮（overlayer）。
5. **改排版**：`settingsStore` 变更 → 渲染层更新 CSS 变量 → `document.fonts.ready` 后重排（100ms 防抖）→ 以旧 locator 复位 → `settings_set` 持久化。

## 4. 数据模型

### 4.1 SQLite Schema（`user_version = 1`）

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

CREATE TABLE books (
  id            INTEGER PRIMARY KEY,
  path          TEXT    NOT NULL UNIQUE,   -- 原文件绝对路径
  file_hash     TEXT    NOT NULL,          -- blake3(文件) 去重/变更检测
  file_size     INTEGER NOT NULL,
  title         TEXT    NOT NULL,
  author        TEXT,
  publisher     TEXT,
  language      TEXT,
  identifier    TEXT,                      -- dc:identifier
  description   TEXT,
  cover_path    TEXT,                      -- AppData\covers\<hash>.webp
  chapter_count INTEGER NOT NULL DEFAULT 0,
  char_count    INTEGER NOT NULL DEFAULT 0,
  added_at      INTEGER NOT NULL,          -- unix ms
  opened_at     INTEGER,
  finished_at   INTEGER
);

CREATE TABLE chapters (
  book_id    INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  ord        INTEGER NOT NULL,             -- spine 序号，从 0 起
  href       TEXT    NOT NULL,             -- zip 内路径
  title      TEXT,
  char_count INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (book_id, ord)
);

CREATE TABLE progress (
  book_id    INTEGER PRIMARY KEY REFERENCES books(id) ON DELETE CASCADE,
  locator    TEXT    NOT NULL,             -- Locator JSON（§4.4）
  percent    REAL    NOT NULL,             -- 0..1 全书进度
  updated_at INTEGER NOT NULL
);

CREATE TABLE bookmarks (
  id         INTEGER PRIMARY KEY,
  book_id    INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  locator    TEXT    NOT NULL,
  chapter_title TEXT,
  excerpt    TEXT,                         -- 定位处前后 60 字，列表展示用
  note       TEXT,                         -- 用户备注
  created_at INTEGER NOT NULL
);

CREATE TABLE annotations (                 -- P1
  id            INTEGER PRIMARY KEY,
  book_id       INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  href          TEXT    NOT NULL,
  locator_start TEXT    NOT NULL,
  locator_end   TEXT    NOT NULL,
  text          TEXT    NOT NULL,           -- 高亮原文
  color         TEXT    NOT NULL DEFAULT 'yellow',
  note          TEXT,
  created_at    INTEGER NOT NULL
);

CREATE TABLE reading_stats (               -- P1
  book_id   INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
  day       TEXT    NOT NULL,              -- YYYY-MM-DD
  seconds   INTEGER NOT NULL DEFAULT 0,
  chars     INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (book_id, day)
);

-- 全文检索：中文按 trigram 分词，支持任意子串匹配
CREATE VIRTUAL TABLE chapters_fts USING fts5(
  text,
  href UNINDEXED,
  ord  UNINDEXED,
  book_id UNINDEXED,
  tokenize = 'trigram'
);
```

**设计说明**

- `file_hash` 而非 mtime：文件被同名替换能识别；导入时 `<3 MB` 才全量哈希，大书用"大小 + 前 1 MB + 后 1 MB"快速指纹。
- 搜索中文：`unicode61` 会把整段 CJK 当成一个 token，无法子串匹配；`trigram` 天然支持 `LIKE`/子串查询，且对中英混排一致。**但 trigram 只对 ≥3 字的查询有效**（1–2 字如"宝玉"无法形成三元组）→ 查询长度 < 3 时直接走 Rust 侧 `instr()` 扫描（章节文本总量通常 < 5 MB，毫秒级）；若 FTS5 未编译，全长度降级为 `instr()` 扫描。两条路径都写单测。
- 不存 zip 内资源：一律按需经协议读取，数据库只存元数据，避免出现两套事实来源。

### 4.4 Locator 定位符规范 v1

```json
{
  "v": 1,
  "href": "OEBPS/text/ch003.xhtml",
  "ord": 2,
  "quote": { "exact": "却说薛家母子在荣府中", "prefix": "……前二十字", "suffix": "后二十字" },
  "offset": 1423,
  "fraction": 0.37,
  "progression": 0.128
}
```

**恢复算法**（`locator.ts`）：

1. 打开 `href` 对应章节（`ord` 兜底）；
2. 在章节纯文本中归一化空白后查找 `quote.exact`：唯一命中 → 定位；多处命中 → 用 `prefix/suffix` 择优；失败 → 下一步；
3. 用 `offset`（纯文本字符序号）定位；
4. 用 `fraction`（章节内比例）兜底；
5. 定位后按 `progression` 校正进度条。

**为什么不用 CFI**：CFI 是 EPUB 规范锚点，但生成/解析复杂且对"改字号重排后的视觉对齐"没有帮助；本项目自用 Locator 已覆盖全部场景，同时保留 `href+offset` 兼容性（如需导入第三方工具的书签，可后续加 CFI 转换层）。

## 5. 渲染与排版规范（本项目最关键的一章）

### 5.1 视口与分页

- **结构**：应用外壳（React）中放一个 `<iframe sandbox="allow-same-origin">`（**必须无 `allow-scripts`**，书内容不执行脚本），foliate `paginator` 在 iframe 内部运行，父子通过 `postMessage` 通信。
- **同源要求**：`iframe` 的文档必须与应用**同源**，否则拿不到 `contentDocument`（注入 CSS、量 `scrollWidth`、拦截点击全部失效）。两种可行做法：
  1. `iframe.src` 指向应用内 `renderer.html`（打包资源，同源），再由 `postMessage` 把章节 HTML 推进去 —— **本项目采用**（复用 Vite 资源管线，调试方便）；
  2. `iframe.src = URL.createObjectURL(new Blob([html], {type:'text/html'}))`（`blob:` 同源）。章节多时注意 `revokeObjectURL` 回收。
  **反面做法**：`iframe.src = 'epub://…/ch01.xhtml'` —— Windows 下与 `http://tauri.localhost` 跨源，直接不可行。
- **分栏**：`#view { column-width: <可用宽>px; column-gap: <gutter>px; height: <可用高>px; column-fill: auto; overflow: hidden; }`，翻页即 `transform: translateX(-n*(pageW+gap))`。**列数由 `scrollWidth` 反算，不可假设**（`column-width` 是最优值，引擎会自行分配余量）；`column-count` 不是分页手段。
- **时序**：注入 HTML → 等待 `document.fonts.ready` + 图片 `load`（或 300ms 超时）→ 测量列数 → 才允许翻页；否则首屏列数会算错。
- **重排**：窗口尺寸/字号/行高变化 → 100ms 防抖 → 记旧 locator → 重排 → 复位到旧 locator（不跳回页首）。
- **页码**：本章页数已知；全书页数在"所有章节都按当前排版参数分页后"才精确 —— 采用渐进策略：已知章节的页数缓存到内存（key 为排版参数 hash + 视口尺寸），未知章节用 `char_count` 线性估算，估算值显示时带 `≈`。
- **滚动模式**：单章连续滚动 + 滚到边界自动加载下一章（保留 2 章 DOM，超出回收），进度仍用 locator。
- **链接与脚注**：在 iframe 文档上统一拦截 `click`（`capture` 阶段，`preventDefault`），按解析结果分派：

| href 形态 | 行为 |
|---|---|
| `#fn3`（同文档） | 站内定位 + `scrollIntoView`；P1 起改为 Popover 预览注文（识别 `epub:type="noteref"`、`doc-footnote`、回跳链接） |
| `ch02.xhtml#n3` | 解析为目标 spine 序号 + 片段 → 渲染层切章后定位片段 |
| `http(s)://…` | `tauri-plugin-opener` 交系统浏览器，**iframe 绝不导航** |
| `mailto:` / 其它协议 | 系统 handler 或忽略（列白名单） |

### 5.2 主题注入与两种模式

| 模式 | 行为 | 适用 |
|---|---|---|
| **净版**（默认，`respectPublisherStyles=false`） | 移除书内所有 `style`/`<link>`，只保留语义标签；由我们的 CSS 完全接管字体、字号、行高、缩进、间距、对齐、图片尺寸 | 绝大多数中文小说/公版书，是"舒服"的主要来源 |
| **原样**（`true`） | 保留书内 CSS（仍强制注入主题色变量与容器约束），仅叠加字号/行高/背景 | 设计排版的书籍、杂志、图文混排 |

注入 CSS 以 `!important` 收紧以下属性：`color / background / font-family / font-size / line-height / text-align / text-indent / max-width / width / margin / padding`；图片统一 `max-width:100%; height:auto; break-inside: avoid`；`position: fixed/sticky` 一律降级为 `static`（书里常见的水印/浮动广告式排版会打乱分栏）。同时中和印刷派生规则：`@page`、`page-break-*`、`body{overflow:hidden}`。注意书内 CSS 可能给 `html`/`body` 或具体元素上色、且后注入的样式表会输给内联样式与更高优先级规则 —— 所以净版模式才直接摘掉书的样式表，原样模式则接受一定程度的配色失真。

**资源引用必须在校验/注入前由 Rust 改写**（不能靠 `<base href>`：它会一并改写 `#fragment` 链接、破坏脚注锚点）：

| 位置 | 处理 |
|---|---|
| `<img src>` / `srcset` | 相对章节目录解析 → `epub://<bookId>/<path>`（路径段百分号编码） |
| SVG `<image href>` / `xlink:href` | 同上 |
| `<object data>` / `<video poster>` | 同上 |
| 书内 CSS 的 `url()`（含 `@font-face`） | **相对该 CSS 文件所在目录**解析后重写；字体最终受 CSP `font-src` 约束 |
| `<link rel="stylesheet">` | 改为 `epub://<bookId>/<css path>`；净版模式下整段丢弃 |
| `<a href="ch02.xhtml#n3">` | 改写为 `data-epub-href="ch02.xhtml#n3"` 保留原值，点击交给宿主处理（§5.1 链接策略） |

### 5.3 中英文排版规则清单

| 项 | 规则 |
|---|---|
| 中文字体栈 | 默认 `"Noto Serif SC", "Source Han Serif SC", "Songti SC", SimSun, serif`；可选思源黑体/思源宋体/霞鹜文楷（后续可内置 OFL 字体） |
| 西文字体栈 | `"Source Serif 4", Georgia, "Times New Roman", serif`；等宽 `"JetBrains Mono", Consolas, monospace` |
| 首行缩进 | 默认 2em（可 0–4em）；不缩进时段落间距 0.8em 作视觉分隔 |
| 两端对齐 | `text-align: justify` + `word-break: normal` + `overflow-wrap: break-word` |
| 避头尾 | `line-break: strict`（Chromium 对中日韩标点的避头尾有内建支持）；**不做**全角标点挤压（`text-spacing-trim` 在 WebView2 上不可靠） |
| 连字符 | 西文 `hyphens: auto`，需 `lang` 属性；中文不启用 |
| 强调 | `strong` 加粗、`em` 斜体；中文斜体为合成倾斜，UI 中提示"部分字体缺失字重会合成" |

| 分隔线/诗行 | `hr` 居中细线；`<br>` 原样保留（诗词排版依赖它） |

### 5.4 安全（书内容 = 不可信输入）

- 章节 HTML 在 Rust 侧先消毒：移除 `<script> <iframe> <object> <embed> <form>`、所有 `on*` 属性、`javascript:` URL、`http(s)://` 外链资源（改为不可点击或标记外链）。
- 渲染器页面与主窗口都设置 CSP。**注意 Windows 上协议 URL 是 `http://epub.localhost/…`，是 `http:` scheme，不是 `epub:` —— 裸写 `epub:` 匹配不到**：
  ```
  default-src 'self';
  img-src     'self' http://epub.localhost data: blob:;
  style-src   'self' 'unsafe-inline' http://epub.localhost;
  font-src    'self' http://epub.localhost;
  script-src  'self';
  connect-src 'self' ipc: http://ipc.localhost
  ```
  （若需要 `https://epub.localhost` 变体，仅在启用 `use_https_scheme` 时替换。）
- 外部链接点击 → 交给系统浏览器（`tauri-plugin-opener`），不在应用内导航。
- 前端不使用 `dangerouslySetInnerHTML` 渲染书内容；书 HTML 只进入 iframe 文档，且经 DOMPurify 二次校验。

### 5.5 性能策略

| 场景 | 策略 | 目标 |
|---|---|---|
| 首屏打开书 | 先渲染第 1 章（或进度章），其余按需 | < 800ms（10 MB 书） |
| 翻页 | 纯前端位移；跨章用预加载的下一章 | < 50ms |
| 预加载 | 闲时预取前后各 1 章的 HTML + 图片清单 | 后台 |
| 章节 HTML 缓存 | Rust 内存 LRU（20 章）+ 磁盘缓存 | 二次打开 < 20ms |
| 书库封面 | 320px webp 缩略图 + 懒加载 + 虚拟滚动 | 500 本滚动 60fps |
| 大书 | 只在需要时打开 zip，句柄复用；单章文本按需解压 | 50 MB 书可用，内存 < 400 MB |
