## 1. 现状盘点（与方案相关的事实）

- 窗口 `decorations: false` 自绘标题栏，`TitleBar` 由书架/阅读两页各自渲染 `actions`；品牌区、返回按钮、窗口三键结构固定。
- 阅读页标题栏现有 6 个图标：加书签 / 排版设置(popover) / 侧栏开关 / 沉浸 / 全屏 / 帮助。书架页 4 个：搜索 / 导入 / 检查更新 / 帮助。
- `ReadingSettingsPanel` 是 Radix Popover 弹出面板：主题 / 字体（宋黑楷）/ 字号 / 行高 / 段缩进 / 段距 / 字距 / 对齐 / 版心 / 目录流向 / 净版开关。
- 已迁移掉的旧选项：v1→v2 去掉 `justify`（并入 textAlign）与 `pagePadding`（页边距改由版心推导）；这就是「之前去掉的选项」的出处——**页边距可以独立回来**。
- 设置持久化在 localStorage（zustand + persist），结构健康，设置页只是换 UI 家。
- 更新链路：tauri-plugin-updater 拉 `releases/latest/download/latest.json`，失败文案 "Could not fetch a valid release JSON from the remote"。
- 发布脚本 `scripts/build-release.ps1`：本地生成 latest.json 后打印「下一步：手工到 GitHub 上传」——**这一步从未执行，所以线上从未有过 latest.json**（两条 release 下载地址实测均 404）。0.3.1/0.3.2 的自动更新从未真正工作过。
- Rust 侧已有：单实例、自定义 epub 协议、SQLite 数据库、日志、window-state。尚未有的：托盘、autostart、close 拦截、字体命令。

## 2. 逐项方案

### 1）顶部菜单栏化，全局固定

**目标形态（一行栏内）**

```
[logo] 返回‹书架› 书名+章节 …… 文件 阅读 视图 帮助 …… [侧栏开关*] [_] [□] [×]
```

- 菜单栏由 `TitleBar` 渲染，**四个页面都相同、永不随内容由书架切阅读而改变**。菜单项类目（P1 实施口径，含审查后修正）：
  - **文件**：导入 EPUB…（仅书架可用）／ 导出批注为 Markdown…（阅读中）／ 打开数据目录 ／ 设置… ／ 退出墨读。
  - **阅读**：添加书签（Ctrl+D）／ 打开目录 ／ 书签列表 ／ 全书搜索（Ctrl+K）／ 重新加载本书 ／ 返回书架。书架态下灰显。
  - **视图**：收起/展开侧栏（Ctrl+B）（书架态灰显）／ 专注阅读（沉浸模式）／ 全屏 F11 ／ 字号增大/减小 ／ 主题（跟随系统、深、浅、羊皮纸、护眼绿）。
  - **帮助**：快捷键与帮助 F1 ／ 检查软件更新…（打开统一更新面板，与设置-关于的按钮同源）／ 关于墨读（转到设置-关于）。
- 顶栏不放搜索键：书架页搜索框本来就在工具栏里；阅读页搜索走菜单/快捷键（侧栏搜索 tab）。
- 导入在书架空态还有大按钮兜底，不损失可发现性。
- 技术要点：用已有的 `@radix-ui/react-dropdown-menu`；菜单触发按钮各自处理 hover/click，周围区域保留 `data-tauri-drag-region`。
- ★ 沉浸模式下整条标题栏仍然隐藏（沉浸的定义就是「只剩正文」），Esc 退出恢复——菜单栏「固定」针对的是书架↔阅读的页面切换，不包含全屏/沉浸两种显式隐藏全部 chrome 的模式。（见讨论点 D4）

### 2）侧栏开关独立且无选中态

- 从菜单候选里排除，作为固定图标按钮放标题栏（阅读页），位置在菜单栏与窗口键之间。
- 不用 `active` 状态：图标恒定（`PanelLeft`），hover 才有底色——符合你的要求「就是默认状态，点一下切换」。
- 收起/展开动画：宽度过渡 160ms，避免侧栏闪现突兀。

### 3）设置独立页面

**导航模型**：App 增加三层视图 `shelf / reader / settings`，入口是菜单「设置…」。设置页也走同一个 `TitleBar`（左上为「返回」，标题「设置」）。

**分组（左列 tab + 右侧表单）**：

| 分页 | 内容 |
|------|------|
| 外观 | 主题（5 种）、正文对齐 |
| 排版 | 字体（预设列表 + 自定义导入，见 6）、字号、行高、段落缩进、段间距、字间距、**页边距（回归）**、版心宽、阅读流向、净版开关 |
| 转换 | 繁体→简体开关（见 7） |
| 行为 | 启动时检查更新（listStorage 迁到设置页）、关闭窗口行为（立即退出 / 询问一次 / 最小化到托盘）、开机自启 |
| 关于 | 当前版本、检查更新按钮、发布页链接、开源许可 |

- **回归旧选项**：`pagePadding`（页边距，范围 0–64px，与版心解耦独立）重新进 `ReadingSettings`，v4 迁移补默认值。`justify` 保持并入 textAlign，不再单独回炉（避免双开关冲突）。
- 排版设置与 localStorage 结构不变，设置页只是新家；阅读页是否还留小面板见讨论点 D2（推荐保留）。
- 附带收益：`HelpDialog`、`UpdateDialog` 的入口全部收敛，顶栏不再出现零散按钮。

### 4）全屏 / 沉浸图标区分

- 全屏保留 `Maximize / Minimize`（约定俗成，F11）。
- **沉浸模式改用 `Focus`（瞄准圆心）图标，语义改为「专注阅读」**——与「全屏=四角外扩」一眼区分。同时快捷键 Ctrl+Shift+F 或单键 `i`?（建议留在菜单，不占新键，避免冲突）。
- 文案：tooltip 分别为「全屏（F11）」与「专注阅读（沉浸）」。

### 5）自动更新修复

**根因（实测）**：`https://github.com/AlanNiew/Modu/releases/download/v0.3.2/latest.json` 与 `releases/latest/download/latest.json` 都是 404。latest.json 只在本地 nsis/ 目录里生成过，从未上传到任何 Release，所以 0.3.1/0.3.2 一直是「App 在拉一个不存在文件」。

**修复（三件套）**：
1. `build-release.ps1` 增加自动上传段：若 `gh` CLI 可用，`gh release create vX.X.X 附带 安装包/签名/便携ZIP/latest.json --notes-file`，不可用时当场给出待上传文件清单并退出（要求显式确认），**不再让上传成为无保护的口头叮嘱**。
2. 增加验证步骤：发布完 `Invoke-WebRequest` 自检 `releases/latest/download/latest.json` 返回 200 才算发布成功。
3. 前端把插件错误串映射成人话：清单拉不到 →「发布服务暂时不可用（可能是清单未发布或网络问题）」；下载中断 →「下载中断，可重试」；验签失败 →「签名校验失败，请去发布页手动下载」。这 3 类不混在一个 String(err) 里。

### 6）字体扩充 + 用户自定义

- **预设列表扩充**（Windows 本机常见 + 网络书常用中文字体名，逐项标注类型）：
  宋体 / 思源宋体、黑体 / 微软雅黑、楷体、仿宋、幼圆、等线、方正兰亭黑/书宋（若检测安装）、霞鹜文楷（若检测安装）、华文楷体、系统默认。
- 保留现有 3 类快捷键义（宋/黑/楷）用于菜单快速切换，设置页里看完整列表。
- **自定义导入**：
  - Rust 新命令 `font_import(path)`：把 .ttf/.otf/.ttc 复制到 `<数据目录>/fonts/`，解析出字体家族名（Windows 解析 name 表可比对 `hea?` 简版，或仅以文件名去重），返回 `{family, file}` 列表存 localStorage。
  - 自定义协议扩展：`epub` 协议增加 `fonts/<file>` 路由读取字体文件流（CSP `font-src` 已含 epub.localhost）。
  - 渲染层注册 `@font-face { font-family: "<family as fontName>"; src: url(http://epub.localhost/fonts/<file>) }`，`fontFamily` 值可指向自定义字体。
  - 设置页提供「已导入字体」管理：删除（物理删除文件 + 清理引用）。
- 版权边界写清楚：App 只加载用户自己导入的字体文件，不打包任何第三方字体（linicing风险归零）。

### 7）繁体转简体 ★

**形态**（对齐同类阅读软件）：设置里一个开关「繁体自动转简体」，默认关。开启后，正文/目录/书签采录文本按转换后文本渲染；书库文件保持原样；关闭即恢复。

**实现位置的两条路线**：

| | A. Rust 层统一转换（推荐） | B. 渲染层 opencc-js 懒加载 |
|---|---|---|
| 范围 | `book_section_html`（正文注入前）+ `book_search`（查询词与索引词同一次转换），**搜索结果与所见一致** | 正文一致，但全书搜索要「双查」（简查询→转繁再查一遍合并去重） |
| 成本 | 要嵌入/绑定繁简词典（生成静态表法零 C 依赖，hash 二级索引次看；opencc-rs/vcpkg 有 C 依赖不优先） | 直接引 npm opencc-js（约 2MB 词典），dynamic import 按需加载 |
| 一致性 | 所有入口同一个函数，无死角 | 正文-搜索口径不同，需另写双查逻辑 |

**推荐 A**：词典生成脚本（一次性，从 OpenCC 官方 TSCharacters/TSPhrases 生成 Rust 静态 map + 短语优先、字表回退），转换函数 `t2s(&str)` 在 api 命令层复用；启动时懒构建词典。工作量约 1 天，收益是「所见即所搜」。
**讨论见 D3**；若选 B，搜索双查后也能用，开发量更小、风险更低。

**转换的两条一致性红线**：
- 转换只发生在**进入渲染前 / 搜索查询时**的书文层面，**不做在 progress/locator 锚点之后**：锚定的引文存的是用户当时看到的文本，切开关重开后锚点若失配，现有 Locator v2 已有「引文失配→按章/仓位回退」机制兜底。
- 高亮（批注 overlay 由 DOM 内选择产生）同源使用转换后 DOM，天然一致。

**落地口径（P4 实现时确定）**：

- 转换范围＝正文 + 目录标签 + 搜索命中标题/摘要；**书名（书架卡片/标题栏）不转**——书架是「藏书的身份证」，保留原书名是同类软件惯例，方案原文只列了正文/目录/书签采录文本。
- 转换模式下的搜索统一走「索引原文 → t2s → 逐章匹配」（短查询本来也走这条路），命中结果缓存 4 本书的转换文本，避免连续输入时整书重转；代价是 ASCII 词在该模式下大小写敏感（原 FTS 路径不敏感），中文书场景可忽略。
- 开关在「打开书 / 重新加载本书」时定格传入 Rust；已打开的书切换开关后需「阅读 → 重新加载本书」整本生效（设置页已提示），进度走既有 locator 恢复链路。

### 8）系统托盘 + 开机自启 + 关闭询问

- **托盘**：Rust 用 Tauri 2 原生 `tray::TrayIconBuilder`（不需要额外 plugin）。菜单：显示主窗口／检查更新／设置…／开机自启(toggle)／退出墨读。**单击（左键）= 显示/还原主窗口，右键 = 菜单**（Windows 惯例）。
- **关闭询问**（关键交互，第一次必弹）：
  - 拦截 `WindowEvent::CloseRequested { api, .. }`：
    - 已记住选择 → 照办（退出：`app.exit(0)`／最小化：`window.hide()`）；
    - 未记住 → `api.prevent_close()`，向前端发事件，弹一次性对话框：
      - 主按钮（推荐）：**最小化到托盘**
      - 副按钮：**退出程序**
      - 复选框：`不再询问`（勾选后写持久化设置）
  - 设置页「行为」分组里可随时改，也能从托盘菜单改。
- **持久化位置**：进 Rust 侧配置（`config.json` 或 DB settings 表），托盘菜单与设置页共享同一个 Rust 命令 `close_policy_get/set`。前端 localStorage 不适合（托盘判断在 Rust 侧）。
- **开机自启**：`tauri-plugin-autostart`（写 `HKCU\...\Run`），托盘与设置页都能切 JS-side toggle。卸载时 NSIS 脚本删除 Run 键（installer.nsi 补一句）。
- **边界情况**：
  - 便携版（无安装器注册表）也允许托盘最小化；开机自启在检测不到 exe 稳定路径时置灰并提示「仅安装版支持」（避免指向临时目录）。
  - window-state 插件在「隐藏而非关闭」路径下不会保存窗口位置：需要退出时主动调一次保存，或监听 hide 前保存，避免下次启动窗口错位。
  - 托盘图标 hover 文案「墨读」，与主窗口未打开时（全部隐藏在托盘）状态一致。

- 繁体 epub 开「简体化」→ 正文简体、关掉恢复、全文搜索口径一致。
- 自导入字体在正文与搜索面板正常出现；删除后自动回退 fallback 字体。
- 关窗第一次弹询问，选「最小化」后托盘恢复如初；勾选「不再询问」后二次关窗静默。

## 4. 风险与不做的事

- **菜单栏 & 拖拽区**：菜单按钮绝对不能再被 `data-tauri-drag-region` 吞掉点击——沿用现有 TitleBarButton 的 props 透传教训，单独提供 MenuTrigger 组件。
- **沉浸隐藏顶栏 vs 菜单「固定」**：模式语义冲突，按 D4 确认。
- **不改**：数据目录结构、foliate 渲染管线、数据库 schema（font 列表进 localStorage 即可）。
- **不做**：暗色主题自定义配色（用户没提）／多窗口／换肤商店（过度设计，版型与第 3 条足够）。
